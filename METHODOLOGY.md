# Methodology
Author: Ethan

The unit of evidence is an attempted task in a fresh container, judged by an independent observable verifier. Each configuration is identified by a SHA-256 of its complete settings. Each trial records task version, fixture and task hashes and actual container image ID. Pin an image by digest and use lockfiles to improve repeatability. Mutable model aliases and provider routing are reproducibility limitations; save exact returned model/response IDs from traces.

Use the same task versions, fixture hashes, limits, sampling settings and repeat counts for each compared configuration. Report temperature and reasoning effort only when explicitly configured and supported. Endpoint adapters differ in tool support, streaming and metadata. Unsupported tool configurations are labeled UNSUPPORTED. Missing credentials are BLOCKED_EXTERNAL. Do not invent API records for either case.

Completion rate uses all terminal attempts as denominator, including failed, timed-out, cancelled, interrupted, unsupported and externally blocked attempts. Configuration groups keep these causes visible. Running trials are excluded until they terminate. Wall time includes setup, model work, tool work, verification and cleanup. Per-request API latency remains separate. TTFT is only measured with streaming and is the first content/tool/reasoning delta from request start, not the first HTTP byte. Nonstreaming TTFT is unavailable.

Median and nearest-rank 95th percentile wall times include failed and timed-out attempts. Variability is sample standard deviation (unavailable below two measured trials). Tool failure frequency is failed tool calls / attempted tool calls. Mean and median token totals require both measured input and output counts; coverage counts accompany them. Cached input is a subset of input, never added a second time. Reasoning tokens are not added again to completion tokens.

Provider usage fields are preserved in raw response traces. Missing values remain null. When a configured endpoint omits cost, request reserves can provide explicitly labeled estimates; they are not provider charges. A reserve uses serialized request byte length plus a protocol margin and configured upper-bound token prices, with maximum output tokens. This is a conservative operational control, not a billing guarantee: tokenizer behavior, hidden provider overhead, pricing changes and interrupted requests can defeat an estimate. Use an independently capped provider key for a hard monetary ceiling. No automatic retries occur, so retry count is zero from the orchestrator, not inferred provider behavior. Run-level spend checks include previous failed attempts.

Total spend is unavailable if any attempt has unknown cost; a separate measured subtotal and coverage identify partial data. Cost per success includes all known failed-attempt spending and requires complete cost coverage and at least one success. Zero denominators produce unavailable values. Reference runs have zero provider spend because they make no provider requests; token counts are unavailable. Reference outcomes validate infrastructure and task verifiers, never model capability.

A single run demonstrates behavior, not universal model quality. Use repeated independent attempts, report task/category composition and uncertainty, and avoid ranking close results without adequate samples. The small bundled corpus is intended for inexpensive smoke comparisons, not a representative measurement of all software engineering. Public tasks can leak into training data. Hidden here means inaccessible to the running agent; the open-source verifier is not a secret from a model's training corpus.

Live model integration unverified until BL-19–22 pass with actual authorized models. A credential-free framework release must retain this limitation prominently.

A tool/request/budget stop does not automatically erase completed work. If time permits verification and the actual output passes, the trial is PASS and retains its termination reason. A zero-tool configuration is supported for deliberate incomplete-work controls. Cancelled and timed-out attempts remain unsuccessful and retain their reason.

Provider implementation references (consulted 2026-10-22): [OpenRouter client tool calling](https://openrouter.ai/docs/guides/features/tool-calling), [Chat Completions schema](https://openrouter.ai/docs/api_reference/overview), and [usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting). Returned metadata, not documentation examples, must supply actual trial measurements.
